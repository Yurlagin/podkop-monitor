# podkop-monitor

Мониторинг доступности серверов [podkop](https://github.com/itdoginfo/podkop) для OpenWrt — страница в LuCI
**Services → Podkop Monitor**.

Что показывает:

- **Секции podkop** — каждый сервер каждой секции (`urltest`, `selector`, `url`): задержка, доступность
  за 24 ч / 7 дней, медиана, полоска истории, график, какой сервер сейчас выбран автовыбором.
  Для секций со списком `telegram` дополнительно проверяется дата-центр Telegram, со списком `youtube` — youtube.com.
- **Устаревшие ссылки в podkop** — каждая ссылка сверяется с одноимённым сервером подписки (адрес, порт, UUID/пароль,
  SNI, ключ Reality, flow, транспорт). «устарел» — через podkop сервер не отвечает, а по ссылке из подписки отвечает;
  «изменён в подписке» — провайдер поменял параметры, но старая ссылка пока работает. Нажатие на отметку показывает
  отличия и заменяет ссылку в podkop ссылкой из подписки (с копией прежнего конфига в `/etc/podkop-monitor/podkop.backup-*`).
- **Автообновление ссылок** (по умолчанию выключено): «только неработающие» — заменять ссылку, если через podkop
  сервер не отвечает две проверки подряд, а по ссылке из подписки отвечает; «все изменённые» — при любом расхождении.
  Есть список исключений для серверов, которые вы правили намеренно. Последние замены видны на странице.
- **Все серверы подписки VPN-провайдера** (если указать ссылку на подписку) — в том числе те, что не добавлены
  в podkop: какие живы, какие быстрые, каких уже нет в подписке. Раз в сутки — какую страну видит YouTube
  через каждый сервер (от неё зависит, будет ли реклама).
- **Управление секциями podkop прямо со страницы** — галочки у серверов и «Удалить выбранные»; «Обновить из подписки»
  для всех изменённых серверов секции сразу; в общем списке подписки — галочки и «Добавить выбранные в секцию …»
  с подсказками (для YouTube — будет ли реклама, для Telegram — задержка до дата-центра, не отвечает ли сервер).
  Серверы ищутся по имени, все правки — одним перезапуском podkop, с копией прежнего конфига.
- **Версию пакета** и кнопку «Обновить», когда на GitHub выходит новый релиз (проверка раз в сутки).

Замеры серверов подписки идут через отдельный вспомогательный sing-box (только `127.0.0.1`, трафик не проксирует)
и не влияют на автовыбор podkop.

## Совместимость

Проверено **только на OpenWrt 24.10** (opkg, LuCI 24.10) с podkop 0.7.22 и sing-box 1.12.
На OpenWrt 25.x (пакетный менеджер apk) **не работает**: пакет собирается только в формате `.ipk`.
На других версиях OpenWrt, podkop и sing-box работа не проверялась.

## Установка

Нужны OpenWrt 24.10 (opkg) и установленный podkop.

### Через LuCI

1. Откройте **System → Software** (Система → Программное обеспечение).
2. В поле **Download and install package** (Загрузить и установить пакет) вставьте ссылку на последнюю версию:
   ```
   https://github.com/Yurlagin/podkop-monitor/releases/latest/download/podkop-monitor_all.ipk
   ```
   и нажмите **OK**.
3. LuCI предупредит, что пакет не из официального репозитория (*Installing packages from untrusted sources…*) —
   нажмите **Install**.
4. Обновите страницу (если пункт меню не появился — выйдите из LuCI и войдите снова).
   Мониторинг появится в **Services → Podkop Monitor**.

Если роутер не может скачать файл по ссылке, скачайте `podkop-monitor_all.ipk` со страницы [релизов](../../releases/latest)
на компьютер и загрузите его в том же разделе кнопкой **Upload Package…** (Загрузить пакет…).

Если LuCI сообщит о недостающих зависимостях (`podkop`, `sing-box`, `jq`, `curl`, `coreutils-base64`), нажмите
**Update lists…** и повторите установку. Обычно они уже стоят вместе с podkop.

Обновлять дальше можно прямо со страницы мониторинга — кнопкой «Обновить», когда выйдет новая версия.

### Через SSH

```sh
wget -O /tmp/install.sh https://github.com/Yurlagin/podkop-monitor/releases/latest/download/install.sh && sh /tmp/install.sh
```

Или вручную: `opkg install https://github.com/Yurlagin/podkop-monitor/releases/latest/download/podkop-monitor_all.ipk`.

### После установки

В LuCI → Services → Podkop Monitor → **Настройки** вставьте ссылку на подписку (ту же, что в Happ / v2rayN /
Hiddify). Поддерживаются Xray-JSON (Remnawave и т.п.) и обычный список ссылок `vless://`, `hy2://`, `trojan://`, `ss://`.
XHTTP-серверы пропускаются — sing-box их не поддерживает.

## Как опознаются серверы

По имени — тексту после `#` в ссылке (например `🇩🇪Germany-4`). Ссылка в podkop сравнивается с сервером подписки
с точно таким же именем. Если провайдер переименует сервер, старое имя станет «нет в подписке», а новое — новым
сервером; если вы переименуете ссылку в podkop, сравнение для неё перестанет работать.

## Как устроено

| Что | Где |
|---|---|
| Настройки | `/etc/config/podkop-monitor` (или вкладка «Настройки») |
| Замеры | `podkop-monitor check` по cron, раз в 5–30 мин; через Clash API podkop и вспомогательного sing-box |
| Подписка, страна YouTube, проверка обновлений | `podkop-monitor daily` по cron, раз в сутки около 4 утра |
| Данные | `/tmp/podkop-monitor` (RAM), раз в час копия в `/etc/podkop-monitor` |
| Вспомогательный sing-box | служба `podkop-monitor`, API `127.0.0.1:9092`, входы `127.0.0.1:32000+N` |

Команды: `podkop-monitor check | sub-update | country | update-check | upgrade | version`,
правка секций: `podkop-monitor apply|remove|add <секция> <имя сервера>…`.
Сверка ссылок — `/usr/libexec/podkop-monitor/drift.sh`, результат в `/tmp/podkop-monitor/drift.csv`.

## Удаление

```sh
opkg remove podkop-monitor
```

Через минуту после удаления стираются и данные (`/etc/podkop-monitor`), включая конфиг с ключами серверов подписки.

## Выпуск новой версии

1. Поменять `VERSION`.
2. `git tag vX.Y.Z && git push --tags` — GitHub Actions соберёт `.ipk` и опубликует релиз.

Локальная сборка: `./build.sh owner/podkop-monitor` → `dist/podkop-monitor_<версия>_all.ipk`.
